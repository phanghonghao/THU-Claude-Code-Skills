# fincomp-deck — 融资比赛 12 页路演 deck（生成 + 体检）

一套从真实大赛项目沉淀出的 **12 页路演结构**，可复用到任何融资/商业大赛场景。
自带"标准范例"（见 `references/`），生成时对照范例的笔法和密度，体检时用它做基准。

> 设计哲学（务必内化）：
> - **大赛 deck ≠ 纯融资 deck**。大赛评委额外重：技术创新性/壁垒、落地可行性、社会与产业价值；弱化估值与融资金额。
> - **每页只回答一个问题**。标题是一句论断，不是主题词（"马来西亚 SME 工厂卡在最难受的中间地带"，不是"市场分析"）。
> - **金句承担记忆点**。每页留一句评委能复述给同事的话。
> - **脚注/来源=可信度**。所有数字、政策、案例必须可溯源；正式版每页带脚注。

## 0. 模式路由（先判断，再动手）

| 用户给了什么 / 说了什么 | 模式 | 入口 |
|---|---|---|
| 描述新项目 / 给原始素材 / "做一版""写一份""生成" | **生成模式** | → §3 |
| 指向一个**已存在**的 deck 文件 / "体检""检查""审""对照""找缺口" | **体检模式** | → §4 |
| 不确定 | 先问：是要从零生成一份，还是审一份已有的？ |

判断不清时**优先问一句**，不要默认。

## 1. 12 页结构总表（核心资产）

每页固定 4 列：序号 / 页名 / 这一页必须回答的唯一问题 / 对应 SixArm 投资人框架页。

| # | 页名 | 唯一要回答的问题 | ↔ SixArm |
|---|---|---|---|
| 1 | 封面 Cover | 我们是谁、为谁解决什么（一句话，不讲技术） | （标题页，SixArm 无） |
| 2 | 问题 Problem | 谁在痛、痛在哪、为什么现有方案不合适 | Problem ✓ |
| 3 | 为什么是现在 Why Now | 为什么是现在做，而不是太早或太晚 | Problem·Bonus + Market |
| 4 | 市场洞察 Market | 真正的空白带在哪、多窄多明确 | Market ✓ |
| 5 | 定位 / 边界 Positioning | 我们是什么、不是什么（缩边界） | Solution + Competition |
| 6 | 解决方案结构 Solution | 我们交付的产品到底由什么组成 | Solution ✓ |
| 7 | Demo / MVP | 现场只证明哪 3 件事 | Validation（大赛特有，SixArm 无 Demo 页） |
| 8 | 全球验证 Global Proof | 这条路全球是否已被证明成立 | Validation + Competition |
| 9 | 壁垒 / 微笑曲线 Moat | 凭什么是我们、护城河怎么长出来 | Competition（可持续优势） |
| 10 | 盈利模式 Business Model | 钱怎么赚、怎么一步步长出高毛利层 | Financial + Sales |
| 11 | 上下游 / GTM | 上游借谁、下游先打谁、怎么卖出第一单 | Partner + Sales + Marketing |
| 12 | 愿景 / Ask / Closing | 接下来做什么、现在要什么 | Investment + Roadmap |

**附 2 页备用页**（Q&A 兜底，不在主 12 页内）：
- 备用页 A：公开案例数字（4 个可量化 case）
- 备用页 B：核心来源总览（数据/政策/案例/客户）

## 2. 每页字段 schema（输出必须遵守）

每一页用以下结构，缺字段体检会扣分：

```
## 第 N 页｜<页名>

### 标题
<一句论断，≤20 汉字，是结论不是主题词>

### 页面内容
- <3-5 条要点，可扫读；数字用反引号包住如 `21.2%`>

### 页面金句              ← 可选但强烈建议（承担记忆点）
> <1-2 行，评委能复述的话>

### 演讲提示              ← 生成版/路演版用此字段名
<这页讲什么、刻意不讲什么、停在哪个瞬间>

（正式版把"演讲提示"替换为 ↓）
### 脚注
`[1]` <证据说明，对应一个来源>

### 来源
[1] <机构/标题>  <URL>

### 建议配图
- 主图：`source/<文件名>`  或  <视觉概念描述>
- 小辅助图（可选）：...
```

**生成两版**（沿用范例的交付习惯）：
- `XX_12页路演版.md`：用 `### 演讲提示`，不带来源，适合直接进 PPT。
- `XX_12页路演版_带脚注正式版.md`：把"演讲提示"换成 `### 脚注` + `### 来源`，适合备注页/答辩备份。

页面之间用 `---` 分隔。

## 3. 生成模式工作流

输入：项目原始素材（深度调研、定位、案例、来源）——用户直接给，或指向项目里的文件。
输出：上面两版 markdown。

步骤：
1. **先抓 5 个锚点**（缺哪个问哪个，别编）：
   - 痛点人群（具体到行业 + Tier + 工位类型）
   - 为什么是现在（人/供给/政策三条同时成立）
   - 唯一空白带（窄到能画出来）
   - 我们交付的"产品"到底由哪些层组成
   - 一条可现场演示的 hero use case
2. **把锚点分配到 12 页**（参照 §1 表，每页只放一个论点）。
3. **逐页填字段**（§2 schema），密度对照 `references/example_12页路演版.md`。
4. **写金句**：每页问自己"评委 10 秒后能复述哪句？"——那句就是金句。
5. **数字/政策/案例全部回链**：正式版每条数字都要有 `[n]` 脚注 + `来源` URL；没有可靠来源的数字**删掉或标"待验证"**，绝不硬编。
6. **配图**：指向 `source/` 下真实素材文件；没有就写视觉概念描述，标 `（待补）`。
7. 产出两版文件，文件名沿用 `XX_12页路演版.md` / `XX_12页路演版_带脚注正式版.md`。

生成完成后，**主动跑一次 §4 体检**（自检），把高危缺口列给用户。

## 4. 体检模式工作流

输入：一份已有 deck（markdown 优先；HTML/DOCX 先提示转 md 或直接读）。
输出：缺口报告（按严重度排序）。

逐项打分（✓ 有 / ⚠ 偏弱 / ✗ 缺失）：

**A. 结构完整性**（对照 §1 的 12 页）
- 12 页是否齐全？缺哪页？（大赛最常缺：**第 9 页壁垒**、**Team 团队页**——SixArm 有独立 Team 页，但本 12 页结构里团队往往被挤进定位/收尾页，需确认团队信息够不够）
- 有没有跑题/冗余页（>12 页要瘦身）？

**B. 每页字段**（对照 §2）
- 标题是论断还是主题词？（主题词 = ✗）
- 页面内容是否 3-5 条可扫读要点？
- 有没有金句？（缺金句 = ⚠）
- 数字是否都带来源？（裸数字 = ⚠，编造数字 = ✗ 且必须删）
- 有没有配图位？

**C. 大赛视角适配**（这是大赛 vs 纯融资的关键差）
- 壁垒/护城河是否讲清（第 9 页）？
- 技术创新性/差异化够不够突出？
- 落地路线 + 里程碑是否具体（第 12 页）？
- 社会价值/产业升级叙事有没有（大赛加分项，纯融资常省略）？
- 是否过度强调估值/融资金额（大赛应弱化为"资源/合作诉求"）？

**D. SixArm 投资人框架补盲**（用 references/sixarm_pitch_deck_template.md 对照）
逐页核对 SixArm 关注点是否被覆盖，重点查这些常漏项：
- **Team**：为什么是"我们"、关键成员、不重复的优势——本结构常缺，**高优补**。
- **Financial 预测**：SixArm 要 3 年销售/损益/现金流预测——大赛可弱，但盈利模式（第 10 页）不能只讲"以后做软件"，要给升级路径逻辑。
- **Validation 指标**：除案例外，有没有可量化 traction 指标（SixArm A16Z 指标体系在 `references/sixarm_pitch_deck_template.md` Appendix C）。
- **Competition 可持续优势**：第 9 页是否讲了"怎么把优势变长期"，而不只是"现在比别人强"。

输出格式：

```
## 体检报告：<deck 文件名>

### 🔴 高优缺口（必须修）
- 第 X 页：...

### 🟡 偏弱（建议改）
- ...

### 🟢 已覆盖
- ...

### SixArm 补盲清单
- ...
```

---

## 5. 输出格式约定

- 文件名：`<项目名>_12页路演版.md` 与 `<项目名>_12页路演版_带脚注正式版.md`。
- 一页一个 `---`，页内用 `###` 子标题，严格遵守 §2 字段名。
- 数字一律反引号：`` `21.2%` ``，方便后续提取进 PPT。
- 来源 URL 单独行，脚注编号 `[n]` 与 `来源` 一一对应。
- 配图路径统一 `source/<文件名>` 前缀。
